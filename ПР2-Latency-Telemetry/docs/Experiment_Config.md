# Конфигурация эксперимента

## Топология
`PingClient` ↔ `PingServer` по UDP, оба процесса локально (`127.0.0.1:6055`), для воспроизводимости запускаются на одной машине без внешней сети.

## Параметры клиента (`PingClient/Program.cs`)
| Параметр | Значение |
|---|---|
| Количество PING | 200 |
| Интервал отправки | 100 мс |
| Таймаут ожидания PONG | 150 мс |
| Интервал проверки таймаутов (`Tick`) | 50 мс |
| Пауза на дозапись хвостовых ответов после последнего PING | 1000 мс |

## Параметры сервера — имитация сетевых искажений (`PingServer/Program.cs`)
Локальный loopback сам по себе даёт RTT≈0 и нулевые потери, поэтому сервер намеренно вносит искажения — иначе телеметрии (детект потерь/дублей/опозданий) нечего было бы обнаруживать.

| Параметр | Значение | Назначение |
|---|---|---|
| `LossProbability` | 5% | Сервер не отвечает на PING — имитация потери пакета |
| `DuplicateProbability` | 5% | Сервер отправляет PONG повторно — имитация дублирования |
| Базовая задержка ответа | Uniform(5, 40) мс | Имитация обычной сетевой задержки |
| `DelaySpikeProbability` | 8% | Вероятность «всплеска» задержки вместо базовой |
| Задержка при всплеске | Uniform(200, 400) мс | Заведомо превышает таймаут клиента (150 мс) → эти PONG приходят уже после того, как клиент пометил запрос потерянным (статус `Late`) |

## Воспроизводимость
- Оба проекта — обычные консольные приложения на .NET 8, зависимостей вне решения нет.
- Сборка: `dotnet build` из `src/`.
- Запуск: `dotnet run --project PingServer`, затем в отдельном терминале `dotnet run --project PingClient`.
- Генераторы случайности (`Random`) не фиксируются seed'ом намеренно — каждый прогон даёт немного другое распределение потерь/дублей, но конфигурация (проценты, диапазоны задержек) детерминирована и задаёт воспроизводимый *характер* эксперимента, а не побитово идентичные числа.
- Результат прогона, использованный в [Latency_Report.md](Latency_Report.md), сохранён как есть в [`latency_samples.csv`](latency_samples.csv) — это конкретные цифры одного запуска, а не сгенерированные вручную данные.

## Среда прогона
- ОС: Windows 11
- .NET SDK: 8.0.425
- Обе стороны на одной машине (нет реальной сетевой задержки/потерь — все ненулевые RTT и все потери в отчёте порождены искусственно на сервере, см. выше)
